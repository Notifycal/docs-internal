## Setup aws-mfa

Assuming you've followed the previous instructions for setting up the AWS CLI:

```bash
$ ~/pyvenvs/aws/bin/pip install aws-mfa
$ sudo ln -s ~/pyvenvs/aws/bin/aws-mfa /usr/local/bin/aws-mfa
$ aws-mfa --help
```

## long-term vs regular AWS Profiles

From [aws-mfa README](https://github.com/broamski/aws-mfa/blob/master/README.md)

> long-term - Your typcial AWS access keys, consisting of an AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY

> short-term - A temporary set of credentials that are generated by AWS STS using your long-term credentials in combination with your MFA device serial number (either a hardware device serial number or virtual device ARN) and one time token code. Your short term credentials are the credentials that are actively utilized by the AWS SDK in use.

We basically need to modify `~/.aws/credentials` and `~/.aws/config` and do the following:

#### Before

```ini
# ~/.aws/config

[profile notifycal]
region = eu-west-1
output = json
```

```ini
# ~/.aws/credentials

[notifycal]
aws_access_key_id = <redacted>
aws_secret_access_key = <redacted>
```

#### After

```ini
# ~/.aws/config

[profile notifycal-long-term]
region = eu-west-1
output = json

[profile notifycal]
region = eu-west-1
output = json
```

```ini
# ~/.aws/credentials

[notifycal-long-term]
aws_access_key_id = <redacted>
aws_secret_access_key = <redacted>

[notifycal]
```

Yes, the `notifical` (short-term) profile is defined, but empty.

## Go go go!

After saving the 2 files, go back to the terminal and do the following:

```bash
# We use the short-term (non-suffixed) profile name
$ AWS_PROFILE=notifycal
$ mfa
INFO - Validating credentials for profile: notifycal
WARNING - Your existing credentials are missing or invalid, obtaining new credentials.
Enter AWS MFA code for device [arn:aws:iam::<redacted>:mfa/<virtual_mfa_device_name>] (renewing for 64800 seconds):057205
INFO - Fetching Credentials - Profile: notifycal, Duration: 64800
INFO - Success! Your credentials will expire in 64800 seconds at: 2024-03-16 18:49:40+00:00
You can now use the profile notifycal

# Verify our identity
$ aws sts get-caller-identity
{
    "UserId": "AIDAVRUVTMT6F4S7AA6NV",
    "Account": "<redacted>",
    "Arn": "arn:aws:iam::<redacted>:user/iamadmin"
}
```

Now if you look at the previously empty `notifycal` profile in `~/.aws/credentials` again, you'll see it's been populated.

```
[notifycal]
assumed_role = False
aws_access_key_id = <redacted>
aws_secret_access_key = <redacted>
aws_session_token = <redacted>
aws_security_token = <redacted>
expiration = 2024-03-16 18:49:40
```

Congrats! You can now use MFA with the AWS CLI!
